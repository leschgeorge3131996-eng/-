研答通

面向论文阅读、报告复核、答辩准备的 evidence-backed 文档问答助手。 评审要记住的不是“更会聊天”，而是“每条回答都能回到 PDF 原文证据”。

锁定样例 中文论文 PDF
主叙事链路 upload -> ask -> citation -> PDF -> refusal
当前定位 证据回链优先于泛化聊天

评审真正关心的痛点

  • 长文阅读成本高，关键信息分散，人工复核效率低。
  • 普通聊天工具能给结论，但很难证明答案来自原文。
  • 答辩和汇报场景最重要的不是“说得顺”，而是“说得出依据”。

最短可验证链路

  1. 上传论文或报告，保留页级结构。
  2. 先检索相关片段，再执行 ask。
  3. 同步返回 citation、页码和证据片段。
  4. 点击 citation 后直接回到 PDF 原页。
  5. 离题问题 refusal，不为看起来聪明而编造。
Judge-facing 结论 我们不是做一个更会聊天的壳，而是把“答案可回原文”做成一条硬链路。
锁定样例：evidence/samples/chinese_llm_spatial_eval.pdf 核心链路固定为 upload -> ask -> citation -> PDF -> refusal

数值能回原文，离题会拒答，strict G3 可复现

最后一页把评审最关心的边界与稳定性说清楚：Q2 是具体数值题，refusal 走 retrieval_no_match，双模型决策和 strict G3 都已经锁定。

锁定问题 2：作者最终的方法排名和总体准确率分别是多少。 当前锁定答案为第六名、56.20%，并且同样带 citation。
离题问题“木星有几颗卫星？” 直接 refusal； 这里的拒答语义是 retrieval_no_match，而不是模型硬猜。

锁定判断

  • Q2 证明系统不仅会概括，也能把具体数值落回原文。
  • 主链路真实跑在无问芯穹 MaaS，当前默认 deepseek-v4-flash（V6 holdout 71/72），rollback qwen3-235b 在 51 题集 51/51。
  • strict G3 六轮 fresh-upload 全通过（首批 spans 13.5s / 12.9s / 15.8s + 续 3 轮），fallback 为 0 / 6。
  • 端侧/近端做解析 / 检索 / 证据定位，云端只推必要片段——Token 压缩即端云协同的量化收益。
收束结论 研答通的差异点不是更会聊天，而是把 evidence-backed QA 做成了可演示、可复现、可追溯的闭环。
