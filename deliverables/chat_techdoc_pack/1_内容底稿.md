## 1. 作品概述

研答通是一个面向**论文阅读、报告复核、答辩准备**的文档助手。核心能力不是泛化聊天，而是**带证据回链的 PDF 文档问答**——立身点只有一句话：**答案必须能回到原文证据**。

围绕这条立身点，一次问答被拆成可核验的四步主链路 `upload → ask → citation → PDF → refusal`：

| 环节 | 做了什么 |
|---|---|
| upload | 上传 PDF / TXT / Markdown，近端解析并保留页级结构（block / line / bbox） |
| ask | 近端先检索相关片段、组织上下文，再调用无问芯穹云端大模型作答 |
| citation | 回答附带 used_chunk_ids 与逐字 evidence_quotes，后端对每条引用做原文子串校验 |
| PDF | 点击 citation 跳回 PDF 原页，bbox 高亮定位证据所在位置 |
| refusal | 检索未命中 / 无真实依据时显式拒答，不做开放域硬答、不编造 |

一句话定位：**让每一个回答都能落回 PDF 原文的、可核验的文档问答助手**——面向学术与答辩场景「说得出处」的刚需。

## 2. 产品能力（对应评分线：产品能力 40）

### 2.1 解决的真实问题
论文与长报告的阅读复核，痛点不在「能不能给个答案」，而在「这个答案凭什么、出处在哪」。普通聊天工具会流畅作答却说不出依据、无法核验——这在学术阅读、报告审核、答辩准备里恰恰致命。研答通正面解决：答得出，更要指得到原文。

### 2.2 为什么这不是「聊天壳」
一条贯穿全链路的四层约束：
1. **解析层**：保留 PDF 页级结构与文本块，证据有坐标可定位
2. **检索层**：先选相关片段、再组织上下文，离题内容在生成前被拦下
3. **生成层**：ask 路径要求模型返回结构化 evidence 依据，引用须逐字可校验
4. **呈现层**：citation 回到 PDF 页面并高亮证据位置，用户可一眼复核

只要检索未命中，系统**直接拒答**，而不是开放域硬答——这是产品可信度的底线。

### 2.3 核心用户价值
- 长文阅读时，快速定位核心信息，省去逐页翻找
- 问答时，答案能回到 PDF 原文证据，可核验、可追溯
- 离题或无依据问题，系统显式拒答，避免「一本正经地编造」
- 对答辩准备场景，citation → PDF 回链的价值高于泛化生成

### 2.4 目标场景
主路径为 **B 端高校实验室 / 课题组席位订阅**，辅以 **C 端答辩季入口**。差异化不是「答得流畅」，而是「答得可验证」。

## 3. 系统架构：端云分层协同（对应赛题主题：端侧/云端协同）

研答通是**端云分层协同**架构，正面回应赛题一「端侧 / 云端协同应用」命题：解析、切块、**本地语义编码**、混合检索、上下文压缩、证据定位等「重而可本地化」的计算放在端侧 / 近端完成；只把命中任务意图的**必要片段**上云，交由无问芯穹 MaaS 大模型**生成**；回答再回到端侧做 PDF 内证据回链。核心范式是**小模型在端理解、大模型在云生成**。

### 3.1 三层职责划分

| 层 | 位置 | 职责 |
|---|---|---|
| 端侧 | 浏览器 / 客户端 | 文件上传与任务输入、结果展示、PDF 证据 bbox 高亮叠加与坐标映射、手动标注与标注页导出、缩放翻页、本地会话态（HttpOnly cookie） |
| 近端服务 | 应用后端（部署节点本地，纯 CPU、零云依赖） | PDF 解析（PyMuPDF 保留页级 block/line/bbox）、结构化切块、本地句向量编码（BGE-small-zh-v1.5 ONNX）、词法 + 语义混合检索、上下文规划与 Token 压缩、bbox 子串定位与逐字证据校验、JSONL 调用日志 |
| 云端 | 无问芯穹 MaaS | ask / summary / outline 大模型生成；端侧 / 近端只上送必要片段 |

### 3.2 真实的端侧 ML 算力实体
近端跑一个**本地句向量模型（BGE-small-zh-v1.5 ONNX）**做语义编码与混合检索，这是真实在本机 CPU 上运行的 ML 前向推理，**零云依赖、物理上可下沉到端侧 / 边缘节点**。本机实测：**权重 90.4 MB、每查询编码约 9 ms、纯 CPU**（建索引为一次性 / 文档级成本，走 warmup 预建）。模型缺失或失败时**自动回退纯词法**，现场绝不因端侧组件崩盘。

### 3.3 诚实标注（口径自律，务必保留）
- **标注一**：PDF 页面图像由近端用 PyMuPDF 栅格化后下发，端侧负责坐标映射与高亮 / 标注交互——端侧做的是「证据呈现 + 交互计算」，**不夸大为「端侧大模型推理」**。
- **标注二**：本地语义检索与高度调优的词法检索在固定基准上**持平、零回归**；价值在①真实端侧 ML 实体②对未知 / 改写措辞、词法弱区（英文公式、多语混排）的语义补召回。**不包装为「检索显著提升」**。

## 4. 核心技术链路（对应评分线：技术能力 40）

### 4.1 文档解析
- 支持 PDF / TXT / Markdown 三类输入
- PDF 解析保留页级结构（block / line / bbox），供 citation 与 PDF 回链使用
- 结构化切块：ChunkService 以 900 字为 target、100 字 overlap

### 4.2 ask 路径：单层 agentic 检索循环
1. 用户提问
2. 近端检索相关 chunk
3. 组织 ask 上下文，调用无问芯穹模型
4. **模型自评证据是否充分**：不足则给出 need_more=true（并在需要新证据时给 followup_query）
5. **有界二次重试（iter ≤ 2）**：用 followup_query 补检索新片段（排除已用 chunk）再问一次；agent_iterations 落日志
6. 提取 used_chunk_ids / evidence_quotes，对每条 quote 做**原文子串校验**（校验不过即丢弃）
7. 组装 citation，回到 PDF 页面做 bbox 证据显示

> 诚实口径：改写补检索分支已实现且有单测覆盖，但固定 demo 集上模型多为单轮收敛、触发的二轮也多为同上下文复核，故生产日志 query_rewrites 多为空——定位为「有界自评重试」，不当作「现场可逐条核验改写」的卖点。

### 4.3 引用不可伪造
ask 返回的每条 evidence_quote，后端都会回到原文做**逐字子串校验**，校验不通过的引用直接丢弃——**引用无法被模型编造**。这是「答案能回到证据」从口号变成工程契约的关键一环。

### 4.4 refusal：检索 / 模型双层拒答
- **检索层**：无命中 → retrieval_gate 直接拒答，离题问题在生成前被拦截（同时省 token）
- **模型层**：检索命中但模型判定无依据 → llm_refused 二次拒答；低置信候选交模型复核，未给可验证证据则拒答

### 4.5 上下文规划与 Token 压缩
ContextPlannerService 按任务意图选片段（ask 走 retrieval、summary / outline 走 coverage），让**只有必要上下文上云**。既是协同的核心节省环节，也直接对应 Token 压缩加分项（见第 6 节）。

## 5. 无问芯穹平台使用（对应评分线：平台使用 20 + 加分项·平台利用率）

主问答链路真实运行在无问芯穹 MaaS 之上，而非把平台「放进环境变量挂个名」。

### 5.1 接入与模型路由

| 项 | 取值 |
|---|---|
| Base URL | https://cloud.infini-ai.com/maas/v1 |
| 默认 QA 模型 | **deepseek-v4-flash**（V6 contract-patch holdout 后从 qwen3-235b 切换） |
| QA rollback | qwen3-235b-a22b-instruct-2507（受信任回滚路径，gold-sample 双模型 3/3 即用它跑） |

### 5.3 多模型平台广度
同一检索流水线下**跨 DeepSeek / Qwen / Kimi / GLM 四大家族实测**：6 模型 × 10 题 = **60 次真实调用、均带 request_id、全部答对**，证明真实深度使用平台、非单模型挂名。

## 6. 关键技术亮点与加分项（对应 4 个加分项）

### 6.1 Token 消耗压缩（加分项）
近端「解析 → 切块 → 按任务意图选片段」三层预处理，让只有必要上下文上云：**长文档 ask 平均节省 86.6% input token、峰值 93.1%**（Attention 论文 10,263 → 704 tokens）。

更硬的口径（**真实平台 token，非估算**）：受控对照「直接喂全文」，唯一变量是检索接地 vs 全文——**22 题集省 4.37×**（49,273 vs 215,113，准确率 22/22 持平）；扩到 **39 题真实论文集省 4.3×**（RAG 38/39，唯一子串漏配已核验非真失败），每条调用带真实 chatcmpl- id 可对账。

> 诚实标注：口径是「同等准确度下省 4.3–4.4× + 能 scale + 能 bbox 回链」，**不是「RAG 更准」**；短文档场景如实标注为约 -4%，不假装所有场景都压得动。

### 6.2 大模型与智能体能力（加分项）
主链路使用无问芯穹大模型 + 单层 agentic 检索循环（检索 → 模型自评证据是否充分 → 有界二次重试 iter ≤ 2，需新证据时改写 followup_query 补检索）+ 检索 / 模型双层拒答；agent_iterations 落日志（真实日志中约 1/4 的 ask 触发了二轮自评）。

### 6.3 商业化潜力（加分项）
主打 **B 端高校实验室 / 课题组席位订阅** + C 端答辩季入口。差异化是「答得可验证」（bbox 级回链 + 逐字校验 + 离题拒答）；毛利侧由 token 压缩支撑（每次问答边际推理成本压低近一个数量级）。

## 7. 验证与评测体系（技术能力支撑 · 诚实优先）

我们把评测当成**找自己问题的工具，而不是包装分数的工具**。验证从锁定小样本一路放大到 3 万级对抗压测，且层层人复核：

| 层级 | 规模 | 结果与口径 |
|---|---|---|
| gold-sample 双模型 | 3 题 | 235b 3/3、32b 3/3，最强可复现 demo 证据 |
| strict G3 复现 | 6 轮 | 6/6 连续 strict fresh-upload，每轮新 file_id，fallback 0/6 |
| 扩展评测 | 51 题 | 默认 deepseek-v4-flash 48/51（94.1%）；V6 extreme holdout 71/72、拒答精确率 100%、引用 98.3%；rollback qwen3-235b 51/51 |
| judged 三层交叉 + 人复核 | 176 题泛化 | 强模型现造全新题判分 88.6%，48 道拒答陷阱 0 编造，主动暴露弱点 |
| 端侧 A/B | 176 题 | 端侧语义检索把过度拒答 6→1（0 新增编造），固定集零变化 |
| 大规模压测 + 5 轮优化 | 33,838 题 | 整体 91.0% 初判通过，16 类文档 14 类 89–99% |
| 多模型广度 | 60 次 | DeepSeek / Qwen / Kimi / GLM 四家族同流水线全过 |

### 7.1 大规模压测 + 5 轮优化（2026-06-05）
累计 **33,838 道全新对抗题**（真实计费、request_id 可对账），其中 **7000+ 道经强模型判分式严格评测**（≈ 1.4 万次真实调用）。方法：强模型现造题 → 真实生产链路作答 → 强模型带原文页判分 → **人逐个复核 FAIL**。

针对「过度拒答」短板做了 **5 轮提召回实验**（端侧 bge-small / 云端 bge-m3 / 调救援阈值 / 短文档全文兜底），结论跨方案一致：**任何「检索空时给模型更多上下文」的方案都会让模型在对抗性无依据题上过度推断 → 幻觉上升**。所以**「检索空就拒答」是精度 / 召回权衡的安全侧，是本产品立身点的正确选择**，验证为对、保持默认不动。这不是没优化成，是有意不塞伤害产品的改动。

### 7.2 评测诚实优先
过程暴露一个方法论发现：**强模型裁判在难数值题上自己也会算错**（finance 类失败约一半是裁判误判），所以 90% 初判通过率被低估、真实系统质量更高。结论：**judged-eval 必须人复核，不能直接拿 pass-rate 当系统准确率**。

## 8. 已知边界与诚实说明（答辩抗追问）

我们不说「没有短板」，而是主动找到、量化短板，并证明当前设计是正确取舍。两个真短板在 3 万题尺度上稳定复现，且**都不在锁定 demo 主链路（中文论文问答）上**。

### 8.1 短板一：多语言内容 → 过度拒答
- 现象：词法检索对非中英文召回弱 → 检索空 → 拒答（multilingual 类约 80%、254 道过度拒答）
- 取舍：已用 5 轮实验证明全局提召回会增幻觉，故保持安全默认
- 可选修复：在确为弱词法 / 多语言场景，端侧语义检索能干净补召回（专项 A/B 9→0、零新幻觉）——端云协同的真实价值，作选项不作默认

### 8.2 短板二：多步表格数值推理
- 现象：finance 类多行 / 多条件表格算术会误读单元格 / 漏行（约 59%）
- 定性：属大模型自身能力边界——连强裁判 qwen3-235b 在同类题上也算错，非检索 / 配置可修
- 后续路线：结构化表格解析 + 受约束计算器 + 单元格级溯源（让模型调工具算，而非脑算）；是加功能、不是赛前 prompt 热补，列为 roadmap

## 9. 结语与后续工作

研答通用一条**可核验的主链路**（upload → ask → citation → PDF → refusal）+ 一个**真实的端侧 ML 实体**，把「端云协同」从叙事做成了可演示、可复现、可追溯的工程事实。后续不再以扩功能为主，而以把现有能力升级为证据链为主：

1. 3 页 PPT 与 5 分钟视频正式成片
2. 如最终演示环境变化，刷新核心截图
3. 多语言召回：端侧语义检索可选开关（已验证干净），默认关以保安全
4. 表格数值：后续接结构化表格解析 + 计算器工具链
5. 保持各材料与 strict G3 / 默认模型口径一致

> 收束语：**evidence-backed QA · 可演示 · 可复现 · 可追溯**

# 附录 B · 口径红线（绝对不能违反）

1. **不说「开放域 100%」**：51/51 是固定扩展集回归，不是任意论文 100%。
2. **端侧语义检索讲「持平 / 补召回」，不夸「显著提升检索准确率」**。
3. **4.37× / 4.3× 必须配「准确率持平」**，口径是「同等准确度下更省 + 能 scale + 能回链」，不是「RAG 更准」。
4. **端侧做的是证据呈现 + 本地语义编码**，不夸大为「端侧大模型推理」（大模型生成在云端）。
5. **两个短板要如实写**（多语言过度拒答、表格数值），并说明是「验证过的安全取舍 / 模型能力边界」，不藏。
6. **summary / outline 弱于 ask**：主打 ask，不假装 summary/outline 同样强。
7. **agentic 二次重试**定位为「有界自评重试」，不当「现场可逐条核验的查询改写」卖点。
