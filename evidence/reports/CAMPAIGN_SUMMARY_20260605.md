# 代金券压测 + 优化 campaign 总纲（2026-06-05）

> 用代金券把"找短板 → 验证 → 优化迭代"跑到底的一次系统性工作。**诚实优先贯穿全程**：跑出什么报什么，不为"做了优化"而塞伤害产品的改动。所有调用真实计费、带平台 `request_id` 可控台对账。

## 规模

- **7000+ 道全新题判分**（≈ 1.4 万次真实平台调用），覆盖 16 文档（2 真实论文 + 14 篇对抗性合成文档）。
- 方法：强模型（`qwen3-235b`）现造题 → **真实生产链路**（`deepseek-v4-flash` + 检索回链）作答 → 强模型**带原文页判分** → **人逐个复核 FAIL**（区分真失败 vs 裁判误判）。
- 工程：自建 **12× 提速的分片并行评测**（`parallel_judged.py` + `judged_eval --shard`），单个 288 题 A/B 从 45 分钟 → ~3 分钟。

## 发现：2 个真短板（7000+ 题尺度上稳定复现）

1. **多步表格 / 数值推理**（最大 `wrong_answer` 簇，54% 在 `finance_table`）：多条件过滤的表格算术会误读单元格 / 漏行。**属大模型自身能力边界**（裁判 `qwen3-235b` 在同类题上也算错），非检索/配置可修。
2. **多语言内容 → 过度拒答**（49% `over_refused` 在 `multilingual_contract`）：词法检索对非中英文召回弱 → 检索空 → 拒答。

> "该拒未拒/幻觉"标签虽多，**人复核后基本是裁判过严 + 自动拒答陷阱太弱**，系统实际很克制（会说"无法确定""文档冲突"）。

## 优化：5 轮迭代 → 诚实收口（详见 `OPTIMIZATION_ROUNDS_20260605.md`）

针对过度拒答试了 5 种"提召回"方案（端侧 bge-small / 云端 bge-m3 / 调阈值 / 全文兜底）。**全部一致：拿"安全"换"幻觉"**——模型一旦被喂更多上下文，就对对抗性无依据题过度推断（硬编参数量/时区/结论）。

→ **结论：「检索空就拒答」是本产品"证据可核验、不编造"立身点的正确设计，验证为对、保持默认不动。** 这不是没优化成，是**有意不塞伤害产品的改动**。

## 已演示的能力（作选项，不作默认）

- **多语言语义检索修复**：专项 A/B 把多语言过度拒答 **9 → 0、零新幻觉**——端云协同的真实价值，确为弱词法场景可选择性启用。
- **多模型平台广度**：DeepSeek / Qwen / Kimi / GLM 四家族实测全通过（`multi_model_eval.md`）。
- **Token 压缩**：长文 ask 省 86.6%；对照喂全文省 4.3×、准确率实质持平。

## 方法论发现（对"怎么诚实评测"本身有价值）

**强模型裁判在难数值题上自己也错**（finance 失败里约一半是裁判误判）→ **90% 初判通过率被低估**，真实系统质量更高；**judged-eval 必须人复核，不能直接拿 pass-rate 当准确率**。与项目"评测诚实优先于刷分"一脉相承。

## 对竞赛的意义

- **技术能力 / 效果增益 / 评测严谨**：7000+ 题对抗审计 + 5 轮优化验证 + 人复核纠裁判错，是工程严谨性的硬证据。
- **答辩可讲**：被问"局限/为什么不修过度拒答"时，有**数据支撑的诚实回答**——"我们试过 5 种提召回方案都会引入幻觉，所以坚持安全默认；多语言场景我们的语义检索能干净修复"。
- **锁定 demo 不受影响**：两个真短板都不在中文论文问答主链路上。
