## ✅ 经人复核确认的真实短板（跨两轮可复现 = 稳定，不是偶然）

### 1. 多步表格 / 数值推理（最该关注）

- **现象**：`finance_table_v6`（一张程序财务表）是两轮里**雷打不动最差**的文档——Round 1 七题 FAIL、Round 2 十二题 FAIL。
- **逐题对表复核（Round 1）**：7 个 wrong_answer 里 **4 个是系统真错**：
  - `gen_ans_8`：把 Boreal 预算 **360 误读成 240** → 奖金资格判错。
  - `gen_ans_9`：「预算>300 的总缺陷数」答 25，实为 37（**漏了 Boreal 行**）。
  - `gen_ans_10`：「未超预算且实支>300」答 0，实为 1（漏 Boreal）。
  - `gen_ans_5`：谎称「表里没 Boreal 实支」（其实是 342）→ 放弃作答。
- **结论**：系统在**多条件过滤 + 跨行聚合的表格算术**上会**误读单元格 / 漏行 / 算错**。真短板。
- **影响面**：仅出现在密集数字表格类文档；锁定 demo（中文论文问答）不涉及。

### 2. 多语言（非中英文）内容检索 → 过度拒答

- **现象**：`multilingual_contract_v6`（含西班牙语/日语条款）两轮共 **9 个 over_refused**——答案明明在原文 p1，系统却拒答。
- **复核**：裁判指出"西语注释中夜间支持需法律团队预批""日语备注交付截止 2027-01-15"等**确实在原文**，系统返回"未检索到足够依据"。
- **根因**：当前默认走**词法检索**（对中文调优），对**非中英文 token 召回弱** → 检索不到 → 触发拒答。真短板。
- **影响面**：多语言文档；锁定 demo（纯中文）不涉及。**注**：这恰好印证了"端侧语义检索（bge-small/bge-m3）补召回"的价值方向。

### 3. 次要：OCR 噪声字符 + 日期算术

- `ocr_noise_register_v6`（数字0/字母O 混淆）、`timeline_sla_v6`（天数差）各有零星 wrong_answer，属字符级/日期级精算的难点，量小。

## ❌ 复核后**排除**的"伪短板"

### 「该拒不拒 / 幻觉」基本不成立（系统其实克制）

初判把 13（R1）/15（R2）题标成 `should_have_refused`，**逐个复核后真问题 ≤ 1–2 个**：
- **系统其实正确拒答了，被裁判贴错标签**：如「有几个 PI 被授权」→ 系统答"**无法确定数量**"；「最终哪个部门审批」→ 系统答"**两处文档冲突、无法唯一确定**"。
- **合理的闭世界推理（弱陷阱）**：如「FFN 用 dropout 吗」→ 论文明说"每个子层输出都加 dropout"、FFN 是子层 → 系统推断**正确**。
- 真正算轻微过度断言的仅 ~1 个（把"实习生例外"答死成"没有任何例外"）。
- **结论**：系统在拒答/边界上**是克制的**，会说"无法确定""文档冲突"。初判的"幻觉"数主要是**裁判过严 + 自动生成的拒答陷阱太弱**。

## 🔬 方法论发现（对"怎么诚实评测"本身有用）

1. **强模型裁判在难数值题上自己也算错**：Round 1 finance 七题 FAIL 里 **3 题是裁判误判、系统其实对**（如 `gen_ans_1` 系统答 Delta 2.5% 最高 = 对，裁判误算成 Cygnus）。
2. **自动生成的"拒答陷阱"质量参差**：很多"陷阱"其实可由原文合理推断，不是真无依据。
3. **启示**：judged-eval 的 pass-rate 在"硬数值 / 边界题"上**双向有噪声**，必须人复核，不能直接拿 90% 当准确率。这条与项目一贯的"评测诚实优先于刷分"一致。
