# 端侧模型本机延迟/体积实测 · 2026-06-03

> 把"可下沉边缘"从口号变硬数。`scripts/edge_latency_probe.py` 只读、离线、零云，对本地
> BGE-small-zh-v1.5 ONNX 在本机 CPU 上实测。**诚实护栏：以下为本机/演示机代表值，不外推
> 为"任意边缘节点"；与端到端 QA 延迟（含云端生成 ~5521ms）是两回事；端侧只做编码+检索、零云。**

## 测试环境

- 机器：AMD64 Zen（Family 25）· 16 逻辑核 · Windows
- 模型：BGE-small-zh-v1.5 ONNX · 512 维 · 纯 CPU · 零云依赖 · `intra/inter_op=1`（生产配置：FastAPI 并发下限线程，故为**单线程**延迟）
- 权重体积：**90.4 MB**
- 测试文档：`chinese_llm_spatial_eval.pdf`（34 chunk）

## 实测数（中位数）

| 指标 | 实测 | 性质 |
|---|---|---|
| **暖态单条查询编码** | **8.8 ms** | **每次 ask 的端侧实时开销——边缘友好** |
| 冷启动（首次 encode，含 lazy 载入 ORT+tokenizer） | 751 ms | 进程内一次性 |
| 批量编码 34 chunk（建索引） | 7,645 ms（≈225 ms/chunk） | **一次性/文档**，单线程 |
| `DenseIndex.build` 全文 | 7,193 ms | 同上，一次性/文档 |

## 怎么诚实讲

- **强项（端侧实时路径）**：查询编码 **~9ms**、零云、90MB 纯 CPU——这正是"可下沉到任意边缘节点"的底气，每次问答端侧只付这点开销。
- **诚实标注（一次性成本）**：把一篇文档**建语义索引**需对全部 chunk 编码，单线程约 **7s/篇**。这是**一次性**成本（懒建于首次查询；演示走 warmup 预建，故不落在 live 查询上——见 `DEFENSE_DEMO_RISK_CHECKLIST` 端侧 smoke 步骤）。单线程是生产并发配置所限；解禁多线程可显著加速，但交付前两周不动该配置。
- **不夸大**：不声称端侧"比云端快"或"边缘秒级建库"；端侧的价值是**零云依赖 + 轻量可部署 + 每查询低延迟**，建索引是可前置的一次性开销。
