# 研答通 海报文案稿

## 标题

`研答通`

## 副标题

`带证据回链的论文/报告问答助手`

## 一句话摘要

面向论文与报告阅读、答辩准备的文档助手。核心能力不是泛化聊天，而是让每一条回答都能跳回 PDF 原文证据。

## 模块一：问题背景

建议标题：

`为什么现有工具不够用？`

正文文案：

- 长文阅读成本高，关键信息分散，答辩前复核效率低
- 普通聊天工具虽然能生成答案，但难以证明答案来自文档
- 在答辩和汇报场景中，用户真正需要的是“说得出处”

## 模块二：方法路径

建议标题：

`我们怎么做`

正文文案：

1. 上传论文或报告
2. 保留页级结构并分块解析
3. 针对问题检索相关证据片段
4. 返回回答、citation 和原文片段
5. 点击 citation 跳回 PDF 页面查看证据
6. 检索未命中时直接拒答

图示建议：

- 用一条流程箭头表示 `upload -> parse -> retrieve -> answer -> citation -> PDF -> refusal`

## 模块四：结果与结论

建议标题：

`当前结果`

## 模块五：适用场景

建议标题：

`适合什么场景`

正文文案：

- 论文精读
- 报告复核
- 答辩准备
- 汇报前快速定位原文依据

## 结尾短句

`让答案回到原文，而不是停在生成。`

## 排版建议

- 上方：标题、副标题、一句话摘要
- 中间：问题背景 + 方法路径
- 下方：真实样例截图 + 当前结果
- 角落：可附 `gold_sample_replay_real_summary_latest.md` 的二维码或短链接

## 不要写进海报的话

- 不要强调邀请码、登录边界
- 不要把更宽样例 replay 当主结论
- 不要把 `summary / outline` 讲成和 `ask` 一样强的 grounding 语义
