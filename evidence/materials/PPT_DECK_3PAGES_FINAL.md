# 研答通 PPT 3页正式提交稿

## 使用原则

- 只讲当前锁定的演示路径（锁定样例 + 锁定问题）。
- 主叙事固定为：`upload -> ask -> citation -> PDF -> refusal`。
- 不把登录、邀请码、`stats panel`、`api docs` 讲成产品亮点。
- 每页只保留一个主结论，不展开历史调试过程。
- 所有稳定性表述统一使用 strict `G3` 口径。

## Page 1：问题与定位

### 标题

`研答通：让每条回答都能回到 PDF 原文证据`

### 副标题

`面向论文阅读、报告复核、答辩准备的 evidence-backed 文档问答助手`

### 页面结构

- 左侧：问题场景与价值判断
- 右侧：最短可验证链路
- 页脚：一句总结

### 页内文案

左侧三点：

1. 长文阅读成本高，关键信息分散，复核效率低。
2. 普通聊天工具能生成答案，但很难证明答案来自原文。
3. 答辩和汇报真正需要的不是“说得流畅”，而是“说得出依据”。

右侧主链路：

`upload -> ask -> citation -> PDF -> refusal`

右侧说明：

- 上传论文或报告并保留页级结构
- 先检索相关片段，再返回回答
- 同时给出 citation、页码和证据片段
- 点击 citation 可以回到 PDF 原页
- 纯离题问题直接拒答，不编造

页脚总结：

`我们不是做一个更会聊天的壳，而是把“答案可回到原文”做成一条硬链路。`

### 讲述口径

“研答通面向论文阅读、报告复核和答辩准备。我们要解决的核心问题不是‘模型会不会回答’，而是‘回答能不能回到原文证据’。所以整套系统都围绕一条最短可验证链路展开：上传、问答、引用、回到 PDF、离题拒答。”

### 配图建议

- 不放复杂截图，优先用简洁流程图或四到五个步骤的视觉链路。
- 可复用 `PROJECT_ONE_PAGER.md` 的问题定义和价值判断。

1. 系统先检索相关片段，再返回回答。
2. 结果面板同时出现回答、citation 和证据片段。

## 删减规则

- 如果一页放不下，先删背景形容词，再删次级指标，不删 strict `G3`、模型决策和主链路。
- 不在主提交页出现：
  - `stats panel`
  - `api docs`
  - broader replay
  - 历史 provider 痕迹
- `summary / outline` 只在答辩追问时补充，不进入 `3` 页主叙事。
