# 答辩防御稿 · 已知边界与设计取舍（2026-06-05）

> 给答辩用：被问"测得怎么样 / 局限在哪 / 为什么不修"时的诚实、有数据支撑的话术。结论经 **Claude + Codex 独立判断一致**：封板前不动核心，保持已验证的安全默认，边界如实讲。

## 一句话定调
我们把评测当**找自己问题的工具**：用 **3.3 万道全新对抗题**（强模型判分 + 人复核）压测，整体 **91% 初判通过、16 类文档里 14 类 89–99%**，并**主动暴露 2 个真短板**——而且**用 5 轮优化实验证明了"不能拿安全换召回"**，所以诚实保持安全默认，不为刷分塞伤害产品的改动。

## 鲁棒性数据（被问"测得怎么样"）
- 规模：16 类文档（2 真实论文 + 14 篇对抗性合成）、**33,838 道全新题**、真实计费可对账。
- 结果：整体 **91.0% 初判通过**（人复核后更高——裁判在难数值题上自己也会算错、压低了分）；**14/16 文档 89%–99%**。
- 两个弱区：`finance_table` 表格数值 59%、`multilingual` 多语言 80%（254 过度拒答）。

## 短板 1：过度拒答（被问"为什么不提高召回"）
**答**：我们试过了，**实测会增幻觉**。
- 做了 **5 轮**："开端侧 bge-small / 云端 bge-m3 / 调救援阈值 / 短文档全文兜底"——**全部一致：过度拒答略降，但模型对对抗性无依据题过度推断、幻觉上升**（如硬编 Transformer 参数量、推算时区）。
- 根因是**基本的精度/召回权衡**，不是缺纪律：我们的 ask 提示词已经很严（evidence 逐字拷贝、缺失值即拒答）。**更松→幻觉多，更严→合法推断题也被拒。**
- 所以**"检索空就拒答"是这条曲线上的安全点**，护住"证据可核验、不编造"的立身点。
- **可选能力**：在确为弱词法/多语言场景，端侧语义检索能**干净补召回**（专项 A/B 多语言 9→0、零新幻觉）——这是端云协同的真实价值，作选项不作默认。

## 短板 2：表格数值推理（被问"表格为什么弱"）
**答**：这是**大模型自身能力边界**，不是检索/配置能修的。
- finance 类多行/多条件表格算术，模型会误读单元格/漏行——**连我们的强裁判 qwen3-235b 同类题也算错**，说明是模型层问题。
- 真要修的**后续路线**：结构化表格解析 + 受约束计算器 + 单元格级溯源（让模型调工具算，而不是脑算）。**这是加功能，不是赛前 prompt 热补**——赛前改 ask 契约不诚实也不稳，故列为 roadmap。

## 边界与后续工作（写进技术文档）
1. **多语言召回**：端侧语义检索可选开关（已验证干净），默认关以保安全。
2. **表格数值**：后续接结构化表格解析 + 计算器工具链。
3. **评测方法**：judged-eval 的 pass-rate 在难数值/边界题双向有噪声（裁判也错）→ 坚持**人复核 FAIL**，不直接拿自动分当准确率。

## 关键记忆点（答辩别说错）
- 不说"我们没短板"——说"**我们主动找到并量化了短板，且证明了当前设计是对的取舍**"。
- 两个短板**都不在锁定 demo 主链路**（中文论文问答）上。
