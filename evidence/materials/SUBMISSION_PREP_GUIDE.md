# Submission Prep Guide

## What This Is

This guide explains how to turn the current repository state into a clean competition/demo submission package.

## Recommended Submission Set

### Must-have

1. `PROJECT_ONE_PAGER.md`
2. `DEMO_SCRIPT_3MIN.md`
3. `SAMPLE_SET.md`
4. `ARCHITECTURE.md`
5. `latest_log_summary.md`
6. latest real replay report
7. refreshed screenshots

### Nice-to-have

1. one experiment note for the English paper validation
2. one experiment note for the Chinese paper validation
3. one short changelog of major milestones

## How To Present The Project

### Product positioning

- Personal intelligent document assistant
- Focused on research and smart office scenarios

### Core value

- Upload document
- Parse document
- Generate summary / answer / outline
- Keep evidence, citations, logs, and statistics

### Why it is not a chat shell

- It has document upload and parsing
- It preserves page-aware structure and chunks
- It uses retrieval for QA
- It returns citations and source chunks
- It logs request behavior and exports evidence reports

## Suggested Demo Story

1. Show the product page and the current document panel
2. Run summary
3. Run QA with citations
4. Run QA with refusal
5. Run outline
6. Show stats panel and evidence reports

## Suggested Final Check Before Submission

- [ ] Local demo still works
- [ ] Real-model replay report exists
- [ ] Latest log summary exists
- [ ] Screenshots are updated
- [ ] One-pager and demo script match the current system behavior
