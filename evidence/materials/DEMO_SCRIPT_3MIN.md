# 研答通 3 分钟演示脚本

## 1. 开场（20s）

大家好，我们的作品叫“研答通”。它是一个面向论文与报告阅读、答辩准备的文档助手。与普通聊天工具最大的区别是——每一条回答都能跳回 PDF 原文证据，不是脱离原文的生成。

## 2. 场景痛点（25s）

用户处理长文档时通常有三个痛点：

1. 很难快速读完并抓住重点
2. 问答时答案缺少依据，难以验证
3. 生成汇报提纲或答辩提纲成本高、效率低

我们想解决的，就是“让用户围绕文档本身完成任务”，而不是只得到一个脱离原文的回答。

## 3. 演示流程（90s）

### 第一步：上传文档

- 展示支持上传 `TXT / Markdown / PDF`
- 展示当前文档的：
  - 字符数
  - 页数
  - 分块数

### 第二步：做摘要

- 输入摘要指令
- 展示系统返回的结构化摘要
- 强调摘要不是简单截断，而是基于覆盖式上下文构造

### 第三步：做问答

- 输入一个文档内问题
- 展示系统先检索相关片段，再生成回答
- 展示“引用依据”：
  - 页码
  - 证据片段
- 强调问答支持“有依据回答”，不是普通聊天式生成

### 第四步：做提纲

- 输入汇报或答辩提纲要求
- 展示系统输出提纲结果
- 说明提纲来自文档内容，而不是独立闲聊生成

## 4. 技术亮点（35s）

当前系统已经具备这些关键能力：

- 页级结构化解析
- 文本分块
- 轻量检索
- 结构化引用依据
- 来源片段展示
- 调用日志与统计面板
- demo 模式与证据目录

这说明我们不是只调用一个模型接口，而是在做一个面向文档任务的端云协同产品。

## 5. 结尾（20s）

下一步，我们会继续提升检索质量，增强摘要和提纲的来源说明，并补齐样例集、评测和比赛材料，让研答通从“可演示原型”进一步推进为“有说服力的参赛作品”。
