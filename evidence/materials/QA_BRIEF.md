# 常见答辩问答提纲

## 1. 你们的作品是什么？

研答通是一个引用可核验的文档问答系统。我们在无问芯穹平台上完成了 51 道题的真实评测，通过率 90.2%，引用准确率 100%，拒答精确率 100%。我们不是为了刷到 100% 而调参，而是诚实地展示了当前检索颗粒度的真实边界。

## 2. 你们的核心差异点是什么？

三个维度：

1. 不是生成后补页码，而是检索-引用-回链的硬链路
2. 不是小样本演示，而是 51 题真实评测（2 篇英文论文 + 2 篇中文 markdown）
3. 不是口头声称，而是 request ID 可核验（每次调用都有 `data/logs/call_logs.jsonl` 留痕）

## 3. 为什么没有一开始就做复杂 RAG 或本地大模型？

我们遵循“先闭环、后增强”的原则。第一阶段先完成上传、解析、云端处理、展示和日志留痕，确保任何时刻都有可运行、可演示版本；在此基础上，再逐步增强结构化解析、分块、检索和引用能力。

## 4. 为什么 90.2% 比某些 100% 更可信？

剩余 5 道失败都是表格单列数据和隐含结论——这不是系统 bug，而是当前检索颗粒度的设计边界。我们可以通过调整检索策略刷到 100%，但那样会牺牲其他场景的准确率。我们选择诚实地展示这个边界，因为 90% 的真实评测比 100% 的调参演示更有说服力。

关键指标：
- 引用准确率 100%（所有返回的页码都能在原文找到对应证据）
- 拒答精确率 100%（纯离题问题走检索闸门拒答，不编造）
- 跨轮一致性 100%（6 轮 fresh-upload G3 全部通过）
- 平均延迟 5521 ms（answerable 问题）

## 5. 当前还有哪些不足？

- `summary / outline` 仍是“来源片段”语义，不是严格逐结论引用
- 检索打分和排序仍有提升空间
- 当前对外体验更适合受控演示，不适合大规模开放访问

## 6. 下一步会做什么？

1. 把当前锁定 gold-sample 证据收口成最终 `3` 页 PPT
2. 把同一口径扩展成最终 `5` 分钟视频
3. 如最终环境变化，再刷新四张核心截图

## 7. 当前推荐演示问题是什么？

当前优先使用这组固定问题，不建议现场临时改题：

1. `这篇论文主要研究了什么问题？`
2. `作者最终的方法排名和总体准确率分别是多少？`
3. `木星有几颗卫星？`

## 8. 你们当前的 G3 证据处于什么状态？

我们当前对 `G3` 的表述已经升级：在 earlier `3` 次 warm-state self-rehearsal 之外，又补了按 `STRICT_G3_EXECUTION_PLAN.md` 留痕的 strict `6` 连跑（分两批：首批 3 轮 + 续 3 轮）。当前主口径是：锁定样例、锁定题组、fresh-upload 条件下，`6` 次连续跑通 `upload -> ask -> citation -> PDF -> refusal`，所有 answerable 都保持 `declared`，所有拒答都走 `retrieval_gate` 或 `llm_refused` 路径，且未触发 fallback。我们仍然不会把这件事讲成开放域泛化证明；它证明的是锁定 judged-demo path 的可复现性。

## 9. 为什么拒答题用“木星有几颗卫星？”这么离题的问题？

因为当前 refusal 的目标是证明：当问题和文档证据完全无关时，系统会直接在检索闸门处拒答，不会编造。我们不把这一步包装成“开放域鲁棒拒答”。如果评审追问文档相邻但无依据的问题，我们的口径是：当前展示的是锁定样例下的 evidence-backed QA，不是开放域聊天。

## 10. 为什么 demo 不主讲摘要和提纲？

`summary / outline` 是支持能力，但当前最强、最能代表差异点的是 `ask -> citation -> PDF -> refusal`。`ask` 这条链路有最严格的证据回链约束；摘要和提纲更多是“来源片段”语义，不是我们当前比赛演示里最该放大的主卖点。
