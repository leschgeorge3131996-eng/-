# 常见答辩问答提纲

## 1. 你们的作品是什么？

研答通是一个面向论文与报告阅读、答辩准备的文档助手。当前比赛主链路里，针对 PDF 文档的 `ask` 结果可以回到原页证据，不是一个脱离原文的聊天壳。

## 2. 你们为什么说这不是聊天壳？

因为系统并不是把问题直接丢给模型，而是有完整的文档任务链路：

- 文档上传
- 本地解析
- 页级结构保留
- 文本分块
- 轻量检索
- 返回 citation 与 evidence snippet
- 调用日志与证据留痕

## 3. 为什么没有一开始就做复杂 RAG 或本地大模型？

我们遵循“先闭环、后增强”的原则。第一阶段先完成上传、解析、云端处理、展示和日志留痕，确保任何时刻都有可运行、可演示版本；在此基础上，再逐步增强结构化解析、分块、检索和引用能力。

## 4. 当前最重要的技术亮点是什么？

1. 页级结构保留与文本分块
2. `ask` 路径先检索再作答，并返回结构化 citation
3. citation 可以回到 PDF 原页做证据展示
4. 锁定样例 replay、Q2 fresh rerun 和 strict G3 都有留痕记录

## 5. 当前还有哪些不足？

- `summary / outline` 仍是“来源片段”语义，不是严格逐结论引用
- 检索打分和排序仍有提升空间
- 当前对外体验更适合受控演示，不适合大规模开放访问

## 6. 下一步会做什么？

1. 把当前锁定 gold-sample 证据收口成最终 `3` 页 PPT
2. 把同一口径扩展成最终 `5` 分钟视频
3. 如最终环境变化，再刷新四张核心截图

## 7. 当前推荐演示问题是什么？

当前优先使用这组固定问题，不建议现场临时改题：

1. `这篇论文主要研究了什么问题？`
2. `作者最终的方法排名和总体准确率分别是多少？`
3. `木星有几颗卫星？`

## 8. 你们当前的 G3 证据处于什么状态？

我们当前对 `G3` 的表述已经升级：在 earlier `3` 次 warm-state self-rehearsal 之外，又补了按 `STRICT_G3_EXECUTION_PLAN.md` 留痕的 strict `3` 连跑。当前主口径是：锁定样例、锁定题组、fresh-upload 条件下，`3` 次连续跑通 `upload -> ask -> citation -> PDF -> refusal`，两次 answerable 都保持 `declared`，拒答都保持 `retrieval_no_match`，且未触发 fallback。我们仍然不会把这件事讲成开放域泛化证明；它证明的是锁定 judged-demo path 的可复现性。

## 9. 为什么拒答题用“木星有几颗卫星？”这么离题的问题？

因为当前 refusal 的目标是证明：当问题和文档证据完全无关时，系统会直接在检索闸门处拒答，不会编造。我们不把这一步包装成“开放域鲁棒拒答”。如果评审追问文档相邻但无依据的问题，我们的口径是：当前展示的是锁定样例下的 evidence-backed QA，不是开放域聊天。

## 10. 为什么 demo 不主讲摘要和提纲？

`summary / outline` 是支持能力，但当前最强、最能代表差异点的是 `ask -> citation -> PDF -> refusal`。`ask` 这条链路有最严格的证据回链约束；摘要和提纲更多是“来源片段”语义，不是我们当前比赛演示里最该放大的主卖点。
