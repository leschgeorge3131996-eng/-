# 常见答辩问答提纲

## 1. 你们的作品是什么？

研答通是一个引用可核验的文档问答系统。我们在无问芯穹平台上完成了 51 道题的真实评测：现场默认 `deepseek-v4-flash` 通过 `48/51`（94.1%），rollback `qwen3-235b` 在同集闭环 `51/51`，更难的 V6 holdout 上 Flash 拿到 `71/72`；引用准确率、拒答精确率均 `100%`。我们不是为了刷到 100% 而调参，而是诚实展示当前检索颗粒度的真实边界。

## 2. 你们的核心差异点是什么？

三个维度：

1. 不是生成后补页码，而是检索-引用-回链的硬链路
2. 不是小样本演示，而是 51 题真实评测（中英论文 + 中文短文档，共 4 文档）
3. 不是口头声称，而是 request ID 可核验（每次调用都有 `data/logs/call_logs.jsonl` 留痕）

## 你说端云协同，端到底算了什么？（最关键追问）

近端（应用后端）跑一个**本地句向量模型（BGE-small-zh-v1.5 ONNX，纯 CPU、零云依赖）**，对查询和文档做语义编码、再做词法+语义混合检索——这是一段**真实在本机运行的 ML 前向推理**，不是把云端的活挪个位置。解析、切块、Token 压缩、证据 bbox 定位也都在近端本地完成；云端无问芯穹 MaaS **只做生成**。所以是"小模型在端理解、大模型在云生成"，物理上可下沉到端侧/边缘。

诚实口径（主动说、别等追问）：这个本地模型与我们已高度调优的词法检索在固定基准上**持平、零回归**（见 `evidence/reports/edge_hybrid_eval.md`），我们**不**包装成"检索准确率显著提升"——它的价值是**真实的端侧 ML 算力实体** + 对未知/改写措辞的语义鲁棒补充；模型缺失或失败自动回退纯词法，现场绝不崩。

## 3. 为什么先做算法预处理、近端只补小模型（embedding）而不是一上来堆本地大模型？

我们遵循"先闭环、后增强"：第一阶段先完成上传、解析、云端处理、展示和日志留痕，确保任何时刻都有可运行、可演示版本；第二阶段在近端补**本地句向量小模型（embedding）**做语义检索（已落地，见上一问），但生成仍交云端无问芯穹大模型——把"重而可本地化"的理解放端侧、把"重算力"的生成放云端，是端云协同的合理分工，也避免本地大模型的复杂度与不可控。

## 4. 为什么诚实的边界口径比"100%"更可信？

旧版曾有 5 道失败（表格单列数据 / abstract 隐含结论 / 小 markdown），是检索颗粒度的真实边界——后经定向检索/上下文修复，rollback 模型在同集已闭环 `51/51`，现场默认 Flash 为 `48/51`（94.1%）。我们从不把 rollback 的 `51/51` 说成默认成绩，也不把固定集回归表述为开放域任意论文 100%。诚实标注边界、不混评测集，比一个调到 100% 的演示更有说服力。

关键指标：
- 引用准确率 100%（所有返回的页码都能在原文找到对应证据）
- 拒答精确率 100%（纯离题问题走检索闸门拒答，不编造）
- 跨轮一致性 100%（6 轮 fresh-upload G3 全部通过）
- 平均延迟 5521 ms（answerable 问题）

## 5. 当前还有哪些不足？

- `summary / outline` 仍是“来源片段”语义，不是严格逐结论引用
- 检索打分和排序仍有提升空间
- 当前对外体验更适合受控演示，不适合大规模开放访问

## 6. 下一步会做什么？

1. 把当前锁定 gold-sample 证据收口成最终 `3` 页 PPT
2. 把同一口径扩展成最终 `5` 分钟视频
3. 如最终环境变化，再刷新四张核心截图

## 7. 当前推荐演示问题是什么？

当前优先使用这组固定问题，不建议现场临时改题：

1. `这篇论文主要研究了什么问题？`
2. `作者最终的方法排名和总体准确率分别是多少？`
3. `木星有几颗卫星？`

## 8. 你们当前的 G3 证据处于什么状态？

我们当前对 `G3` 的表述已经升级：在 earlier `3` 次 warm-state self-rehearsal 之外，又补了按 `STRICT_G3_EXECUTION_PLAN.md` 留痕的 strict `6` 连跑（分两批：首批 3 轮 + 续 3 轮）。当前主口径是：锁定样例、锁定题组、fresh-upload 条件下，`6` 次连续跑通 `upload -> ask -> citation -> PDF -> refusal`，所有 answerable 都保持 `declared`，所有拒答都走 `retrieval_gate` 或 `llm_refused` 路径，且未触发 fallback。我们仍然不会把这件事讲成开放域泛化证明；它证明的是锁定 judged-demo path 的可复现性。

## 9. 为什么拒答题用“木星有几颗卫星？”这么离题的问题？

因为当前 refusal 的目标是证明：当问题和文档证据完全无关时，系统会直接在检索闸门处拒答，不会编造。我们不把这一步包装成“开放域鲁棒拒答”。如果评审追问文档相邻但无依据的问题，我们的口径是：当前展示的是锁定样例下的 evidence-backed QA，不是开放域聊天。

## 10. 为什么 demo 不主讲摘要和提纲？

`summary / outline` 是支持能力，但当前最强、最能代表差异点的是 `ask -> citation -> PDF -> refusal`。`ask` 这条链路有最严格的证据回链约束；摘要和提纲更多是“来源片段”语义，不是我们当前比赛演示里最该放大的主卖点。
